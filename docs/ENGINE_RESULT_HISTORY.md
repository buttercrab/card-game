## Replay authority, identity and privacy

Use a stable historical identity including room epoch, session/archive ID and recorded hand number. Copy authorized records into immutable ownership. Historical rendering uses the record's frozen rules, contract, names, participant IDs, payoffs and plays, even after current settings, seats or names change. Validate the unknown `rules`/`view` boundary; malformed or summary-only records yield an unavailable-replay explanation without breaking the live table.

`book_record` explicitly stores `G::view(game, Viewer::Spectator)`. The server test `room/lifecycle.rs::recorded_views_keep_private_discards_private_after_restore` proves recorded private discards and hand remain absent. Archive projection must never fill those omissions from live hand/kitty/discard caches or remembered declarer views. No absent face may be manufactured from a card count.

A current authenticated declarer may have a more privileged live Done view. If shown, its private exchange details remain audience-scoped and are erased on revocation/actor replacement. They must not be promoted into public archive data or persisted as device-stat keys. Current-hand replay built from `current_hand` follows that record's spectator privacy even for the declarer. The UI explains hidden discards rather than implying an empty exchange.

Live gameplay may advance while a read-only replay stays open. Keep its authorized snapshot stable, disarm the background, and close back to the latest table. Retaining public archive content must never retain prior scene-private hand nodes or animation data. A private live replay retires immediately on incompatible audience changes. Late navigation from a retired disclosure cannot target a reopened item.

## Truthful once-only completion storage

Completion storage belongs to a narrow host bookkeeping boundary, not pure projection, planner, paint or animation callbacks. An authenticated original participant qualifies by stable participant ID in the completed record, not simply the current seat index. Observers, replacements, later joiners and opening old archives do not create personal records.

Use a normalized summary and explicit hand/actor identity for idempotence. Do not copy the legacy `JSON.stringify(done)` key: it embeds replay data, potentially private discards, and does not distinguish repeated identical deals reliably. Include room epoch/session/hand and actor identity; retain only summary fields needed by device statistics. Keep the existing 1,000-summary bound and document the deduplication retention horizon rather than claiming unlimited exactly-once persistence.

The current `stats.ts::recordHand` returns true after a failed write; achievement saving independently swallows errors. Do not reuse those return values as persistence acknowledgements. Introduce explicit stored/duplicate/failed/unsupported outcomes, preserve malformed existing raw storage on refusal, and define partial-write/crash recovery across stats and achievement keys. Deriving awards idempotently from validated summary history can repair a stats-written/awards-not-written interruption; merely gating awards on `recordHand` returning fresh cannot.

Achievements and device statistics remain separate from server standings and ResetScores. Confirmed device-record deletion clears statistics as the original does; it does not erase earned achievements or mutate the room. Local storage concurrency guarantees must be stated honestly; localStorage does not supply cross-tab compare-and-swap.
