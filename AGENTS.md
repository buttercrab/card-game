# Card-game QA routing

For rendered game UI, engine presentation, interaction, responsive or animation work, use `$strict-game-qa` when available. Local installation: `~/.codex/skills/strict-game-qa/SKILL.md`. Read [docs/QA_PROCESS.md](docs/QA_PROCESS.md) for the project contract. If unavailable, apply that document and report the missing skill; do not claim invocation.

Focused fixes check the failing case and adjacent transitions. Full engine/migration completion or readiness requires the full acceptance campaign. Preserve original Mighty design and intentional card layering unless the user changes that contract. Tests/geometry/performance are not visual approval.

The recovered user decisions and concrete renderer references are in [docs/DESIGN.md, Engine migration](docs/DESIGN.md#engine-migration-preserve-the-approved-ui). Foundation proofs are not redesign approval.

This routing does not authorize deployment, publication, automatic commits, resets or changing existing dirty work. Read-only QA does not authorize product fixes. Keep generated evidence outside the repository unless committed artifacts are requested.
